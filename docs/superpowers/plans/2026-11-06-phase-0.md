# Phase 0 implementation plan

Goal: establish reproducible cross-client references and a reusable Compose visual foundation.
Spec: Kairos-Android-Roadmap.md, milestone 0, approved in the implementation request.
Architecture: keep existing data/ui/utils packages, navigation and repositories. Theme and shared components own visual choices; the app shell owns system/chrome/keyboard insets.

## Constraints and decisions

- No shared schema, authentication, AI transport or persistence changes in this phase.
- Web app.css defines shared neutral colours and existing theme names. iOS defines mobile content hierarchy and 20-point page margins. Preserve native Android interactions.
- Use existing Material/Compose dependencies and system fonts; do not distribute Apple fonts.
- Screens consume measured shell padding once. Nested scaffolds do not reserve system bars again.
- Existing behaviour and Android-only screens remain available.

## Tasks

- [x] Record immutable repository heads, screen/state inventory, field/API contracts and visual token provenance in docs/phase-0-reference.md.
- [x] Define semantic theme roles, spacing/shapes and complete typography in ui/theme. Add contrast coverage for every supported accent in light/dark; execution remains a verification gate.
- [x] Build shared surfaces, buttons, fields, task rows, dialogs, menus, sheets, state feedback and an inset-aware scaffold in ui/components. Keep legacy Premium* call signatures as compatibility wrappers.
- [x] Integrate shell padding and accessible navigation; remove compensating offsets in shell destinations; put AI input in the measured column.
- [x] Add isolated Dashboard, task-detail and AI component previews with populated, empty, loading, error and editing states, both appearances and a large-font small-phone case.
- [ ] Build/test when tooling allows, review diff and reference matrix, and publish a reviewable branch. Merge only after required checks pass.

## Verification focus

Long names and large fonts must wrap without clipping controls. Disabled buttons must retain disabled colours. All completion/menu actions must expose labels and 48dp touch targets. IME padding must be consumed once. Gesture/button navigation and landscape cutouts must not cover content. Empty/error states must not claim successful saves or loading failures without actual state evidence.
